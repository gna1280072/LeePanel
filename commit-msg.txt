fix(sudo): globally wrap invoke so ask-mode sudo prompt fires on ANY command

Reported: with sudo password policy = "ask each time", the password dialog
never appeared. Root cause: only a handful of call sites used
invokeWithSudo; every other command (including read-only panel loads that
also go through the sudo-wrapped exec layer) hit SUDO_PASSWORD_REQUIRED and
just rendered the raw error string.

Fix: sudoPrompt.tsx now exports a global `invoke` that wraps the raw Tauri
invoke — on SUDO_PASSWORD_REQUIRED/INCORRECT it extracts sessionId from the
call args, opens the shared password dialog, caches the password via
ssh_set_sudo_password, and retries once. All 27 business files now import
this wrapper instead of '@tauri-apps/api/core' (raw import kept only inside
sudoPrompt itself).

Dialog queue hardened: FIFO per session + fan-out merge for concurrent
requests on the same session (one prompt, all retried) — previously a
second concurrent request overwrote the pending one, leaving the first
Promise unresolved forever.

invokeWithSudo kept as a pass-through shim for existing call sites (global
invoke already handles prompting; avoids double dialogs).

Verified: tsc clean, 22 vitest i18n pass.
